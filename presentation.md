# Post-Quantum Handshakes: ML-KEM (FIPS 203) vs RSA — Simple Intro

## What is ML-KEM (Kyber)?
- A post-quantum Key Encapsulation Mechanism standardized as FIPS 203.
- Purpose: establish a shared secret over an insecure channel, even against future quantum attackers.
- Think of it like RSA key exchange, but designed to resist quantum computers.

## What is a Handshake?
- A quick exchange to agree on a shared key for encryption.
- We measured the compute time for common steps on both client and server.

```
Client                                   Server
  |--(public info: alg + server pub)-->   |
  |                                       |
  |-- Encapsulate to server pub  -------->|
  |                                       |-- Decapsulate (get shared secret)
  |                                       |-- Encapsulate to client pub
  |<----------------  ciphertext  --------|
  |-- Decapsulate (get shared secret)     |
  |-- Derive final key                    |-- (Optional) sign/verify
```

## Experiment Setup
- Both RSA-2048 and ML-KEM run via Python (liboqs for KEM, cryptography for RSA).
- We record timings for:
  - Client: keygen, encrypt, decrypt
  - Server: encrypt, decrypt

## Key Takeaways
- ML-KEM is designed to be fast on modern CPUs, often comparable to or faster than RSA for handshake operations.
- Ciphertexts and keys differ in size and structure, but the main outcome is the same: both sides derive the same shared key.
- Post-quantum readiness: adopting ML-KEM prepares systems for the era when large quantum computers could break RSA.
